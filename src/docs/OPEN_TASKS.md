## Плата: FLOS 6.14 и демо parity работают (2026-11-10, ветка `board/t80pa-pll`, сборка `ise/osca676p_t80pa.xst`, `ise/work/osca_t80pa23_flos614.kg1`)
Баннер в правильных цветах, курсор, приглашение. Процессор T80pa (VHDL, фазы настоящего Z80). Что было причиной сбоев на плате и что сделано:
- [x] `clk16` делался счётчиком через BUFG: его фронты отставали от `clk96` (~0,5 такта), а пути между доменами ISE не проверял вообще
      (отдельный PERIOD). Теперь оба такта из одного PLL (`karabas_go_osca_top.v`), ISE сам выводит их фазу; счётчик слотов обёртки
      подстраивается под `clk16` (`KG_PLL16`). Нарушения удержания исчезли, пути между доменами анализируются.
- [x] `kg_osca_mem.v`: решения о записи только в тактах 3 и 5 (входы стабильны >= 2 тактов; замеры `KG_MEMLOG`), адрес экрана в последней ступени `ma`.
- [x] `kg_osca_sdram.v`: адрес (и адрес упреждающего чтения) регистрируется; `rdata`/`rd_valid` — регистры, без лишнего такта для завершающегося чтения;
      нет упреждающего чтения между запросом шины ядром и её получением (иначе звуковой DMA опаздывал).
- [x] `kg_osca_cpu.v` (T80pa): спад WR# задержан на 2 такта, MREQ#/IORQ# удерживаются 2 такта после подъёма (RAM регистров спрайтов).
- [x] Палитра (`osca_core.v`): запись по началу строба (`cpu_write` активен низким, оригинал пишет по его спаду).
- [x] UCF: многотактные ограничения из фиксированных фаз T80pa и слотов обёртки; ложные пути (таблица `maths_assist`, звук и SPI -> опкодный путь T80)
      описаны с обоснованием. Сборка: все ограничения выполнены (Timing Score 0). Самотесты SRAM/видео-RAM в этой сборке выключены (`KG_NO_MEMTEST`).
- [x] Симуляция с фазами T80pa: `sim/kg_tv80pa.v` (процесс шины T80pa на `tv80_core`, сверен с GHDL такт в такт), `-DKG_CPU_T80PA -DKG_CPU_TV80PA`.
      Регрессия 11/11 на tv80 и на модели T80pa, `make unit` PASS.
- [x] FLOS 6.14 (`roms/ram_image_614.bin/.hex`, из `v6z80p/FLOS/FLOSv614.OSF`) — образ по умолчанию для платы (`scripts/make_kg1.py`); проверен на плате
      (`ise/work/osca_t80pa16_flos614.kg1`). Регрессия в симуляции по-прежнему на FLOS 5.68 (`sim/roms/ram_image.hex`, эталон `sim/golden/flos.png`).
- [x] Калибровка SDRAM портила образы длиннее 20142 байт (проверяла и переписывала только их начало, хвост оставался записанным до подбора

      `kg_osca_ps2dev` принимал запрет тактов хостом ПОСЛЕ стоп-бита за прерывание кадра и слал байт снова (OSCA с v675 держит такты низкими

      чтения (счётчик состояний стоит, адрес держится). Наши lc-тесты переходов не делали. Проверено на плате.
