# Тайминг интерфейса SDRAM на 96 МГц (расчёт и симуляция; ISE ещё не запускался)

## Схема (ветка `wip/sdram-iob-timing`)
- `clk96`, T = 10,417 нс. `SDR_CLK` = инвертированный `clk96` (ODDR2: D0 = 0, D1 = 1), то есть фронт у микросхемы на половину такта позже фронта запуска команд.
- Команды, адрес, DQM, данные записи выходят из регистров в IOB по фронту `clk96`. READ уходит на такте c2, микросхема принимает его в c2 + T/2 + Tclk,
  CAS latency 2, данные захватывает регистр `dq_iob` (IOB) по фронту c6 (c2 + 4T), контроллер берёт слово на c7.
- Параметры микросхемы (MT48LC16M16A2 по тестбенчу NanoMig): tAC 5,4 нс и tOH 2,7 нс взяты оттуда; tIS 1,5 нс и tIH 0,8 нс — класс -7E из моей памяти, **сверить с даташитом реальной микросхемы**.

## Условия (Tclk — клок-фронт на ODDR2 → вывод CLK микросхемы; Tin — вывод DQ → вход триггера IOB; Tsu/Thd — setup/hold этого триггера; Tco — фронт → выход IOB на пине)
| | Условие | Число |
|---|---|---|
| A | данные дошли до захвата: Tclk + Tin + Tsu ≤ 4T − T/2 − 2T − tAC | ≤ 10,2 нс |
| B | данные держатся после захвата: Tclk + Tin − Thd ≥ 4T − 3,5T − tOH | ≥ 2,5 нс |
| C | setup команд/записи у микросхемы: Tco(max) ≤ T/2 + Tclk − tIS | ≤ Tclk + 3,7 нс |
| D | hold команд/записи: Tco(min) ≥ Tclk + tIH − T/2 | ≥ Tclk − 4,4 нс |

## Что показала симуляция (`sim/tb_sdram_model.v`: транспортные задержки, окно данных tAC/tOH с X вне окна, проверка setup/hold микросхемы)
Модель: Tco = 4,0, Tin = 1,5, Tsu = 0,5, Thd = 0,3 нс; `sim/tb_kg_osca_sdram.v` с `P_DCLK`, `P_TCO`, `P_TIN` (`-P` в iverilog).
| Развёртка | Проходит | Не проходит | Расчёт |
|---|---|---|---|
| Tclk (при Tco = 4) | 2…8 нс | 0, 1 и 9…11 нс (12 и больше повторяют окно с периодом T) | 1,3…8,2 нс |
| Tco (при Tclk = 3) | 0…6 нс | 7 нс и больше | ≤ 6,7 нс |
Типичный прогон (Tclk 3, Tco 4, Tin 1,5): 0 ошибок данных, 0 нарушений таймингов, 0 нарушений setup/hold; задержка DMA до 9 тактов, поток копроцессора 0 тактов.

## Оценка положения проекта в окне (мои оценки, не данные ISE)
Tclk ≈ 3,8–4,3 нс, Tco ≈ 4–4,5 нс, Tin ≈ 1,6 нс: A даёт ≈ 6,4 ≤ 10,2, B ≈ 5,6 ≥ 2,5, C ≈ 4,5 ≤ 8 — запас больше 3 нс. **Проверить сборкой.**

## Как сверить с ISE
1. Собрать `make -C ise UCF_EXTRA=sdram_offsets_wip.ucf` на ветке `wip/sdram-iob-timing`.
2. В `work/osca676p.twr` найти: clock-to-pad `SDR_CLK` (= Tclk с учётом трассы платы, её добавить вручную, порядка 0,2–0,5 нс), clock-to-pad для `SDR_A/BA/DQM/RAS_N/CAS_N/WE_N/DQ`
   (= Tco), `pad-to-setup` для `SDR_DQ` (Tin + Tsu), hold (Thd).
3. Подставить в таблицу условий. В `ise/sdram_offsets_wip.ucf` OFFSET IN BEFORE = 10,27 − Tclk (VALID 7,7), OFFSET OUT AFTER = Tclk + 3,71; сейчас в файле Tclk = 3,9.
4. Если условия не выполняются: сдвиг фазы `SDR_CLK` (PLL_ADV с `CLKOUT_PHASE`, на `DCM_CLKGEN` фазы нет), захват по другому фронту, задержка входов через `IODELAY2`.

## Ограничения модели
Постоянные задержки (без разброса min/max, без PVT), без перекоса между битами шины, без трассировки платы, 3,3 В LVCMOS DRIVE 4 FAST NODELAY по UCF соседних ядер.
